# Simulation Scenarios

All scenarios run in Gazebo Harmonic on the x86 host. The worlds live in
[`ros2_ws/src/demo_simulation/worlds/`](../ros2_ws/src/demo_simulation/worlds/).
Spawn poses and scene-camera framing for each world are defined in one place,
[`demo_simulation/scenarios.py`](../ros2_ws/src/demo_simulation/demo_simulation/scenarios.py).

## Scenario catalog

| ID | World | Purpose | Checks |
| --- | --- | --- | --- |
| S0 | `quadruped_empty.sdf` | Flat plane, reference | Standing, trot, velocity tracking |
| S1 | `quadruped_ramp.sdf` | 6° ramp | Balance and tilt limits on an incline |
| S2 | `quadruped_rough.sdf` | Rough terrain | Foot placement, estimator off the plane |
| S3 | `quadruped_corridor.sdf` | Corridor | Lidar and costmap in a confined space |
| S4 | `quadruped_objects.sdf` | Objects in view | Camera and perception contract |
| S5 | `quadruped_objects.sdf` + Nav2 | Obstacle avoidance | Detections → costmap → MPPI → gait loop |
| **S6** | `quadruped_maze11.sdf` | **Maze (official demo)** | SLAM, frontier exploration, AprilTag exit detection, escape validator |

The differential-drive fallback (`ROBOT_TYPE=diffdrive`) uses the `warehouse.sdf`
world from `nav2_minimal_tb4_sim`, with a static map and AMCL.

## Selecting a scenario

`ROBOT_TYPE` selects the robot and its matching navigation stack together.
Without further arguments each robot loads its official world: the maze for
the quadruped, the warehouse for the differential-drive robot.

To load another world with the Compose `sim` service, pass an absolute path
inside the image through `SIM_ARGS` in `docker/.env`:

```bash
SIM_ARGS=world:=/ws/install/demo_simulation/share/demo_simulation/worlds/quadruped_ramp.sdf
```

For quick iteration on the plant alone, use the standalone runner. It rebuilds
the simulation packages from the working tree, so local edits apply without an
image rebuild. A bare file name is resolved in the package's `worlds/`
directory:

```bash
MAZE_MODELS=$HOME/ros_maze_worlds/models scripts/run_quadruped_sim.sh quadruped_maze11.sdf
```

## The maze (S6)

- **Mesh:** `maze11` from [`cafemesa/ros_maze_worlds`](https://github.com/cafemesa/ros_maze_worlds),
  mounted at runtime through `MAZE_MODELS` (see [`docker/models-extra/`](../docker/models-extra/README.md)).
  If the variable is missing, the launch aborts and names the variable. It does
  not load an empty maze silently.
- **Geometry:** 1.20 m corridors and 35.4 m² of navigable area, all one
  connected component. The Go2 trunk is 0.70 × 0.31 m.
- **Exit marker:** an AprilTag (`36h11`, id 0) at the exit
  (`worlds/maze_exit_tag.png`, generated by
  [`tools/maze/generate_maze_exit_marker.py`](../tools/maze/generate_maze_exit_marker.py)).
- **Ground truth:** `maze_escape_validator` publishes `/demo/maze/escaped` from
  the robot's odometry. The explorer never reads it.
- **Spawn:** `(0, 0)`, yaw 90°, declared by the world.

The maze analysis tools in [`tools/maze/`](../tools/maze/) work offline on the
STL mesh:

| Tool | Purpose |
| --- | --- |
| `maze_fit.py` | Check whether a `ros_maze_worlds` maze fits the Go2, choose scale and spawn |
| `maze_geodesic.py` | Compare straight-line and corridor distances to the exit |
| `maze_route.py` | Derive waypoints along the exit route |
| `generate_maze_exit_marker.py` | Regenerate the AprilTag texture |

## Checking a scenario

[`tools/diagnostics/scenario_check.py`](../tools/diagnostics/scenario_check.py)
is a read-only check of the topic contract. It reports rates, `/clock`
progress, lidar content and camera frames:

```bash
python3 tools/diagnostics/scenario_check.py --seconds 20
```

It needs a ROS 2 environment: a native Jazzy installation with
`source scripts/env.sh`, or the `tools` container.
